## 部署方式概述

系统支持多种部署方式：

1. **Docker Compose**（推荐）- 一键部署，包含所有依赖
2. **传统部署** - 直接在服务器上运行
3. **Kubernetes** - 适合大规模生产环境

---

## Docker Compose 部署（推荐）

### 前置要求
- Docker 20.10+
- Docker Compose 2.0+

### 1. 快速启动（使用 SQLite）

这是最简单的部署方式，适合测试和小型生产环境：

```bash
# 克隆项目
git clone <repository-url>
cd workspace

# 构建并启动
docker-compose -f docker-compose.sqlite.yml up -d
```

### 2. 使用 MySQL 部署

```bash
# 使用 MySQL 数据库启动
docker-compose -f docker-compose.mysql.yml up -d
```

### 3. 使用 PostgreSQL 部署

```bash
# 使用 PostgreSQL 数据库启动
docker-compose -f docker-compose.postgres.yml up -d
```

### 访问应用

部署成功后：
- 前端应用：http://localhost
- API 服务：http://localhost/api

### 查看日志

```bash
# 查看所有服务日志
docker-compose logs -f

# 查看特定服务日志
docker-compose logs -f api
docker-compose logs -f web
```

### 停止服务

```bash
# 停止但保留数据
docker-compose down

# 停止并删除数据卷（谨慎使用）
docker-compose down -v
```

## 传统部署方式

### 前置要求
- Node.js 20+
- pnpm 8+
- Nginx（可选，用于生产环境）

### 1. 安装依赖

```bash
# 安装 pnpm（如果没有）
npm install -g pnpm

# 安装项目依赖
pnpm install
```

### 2. 配置环境变量

```bash
# 复制环境变量模板
cp apps/api/.env.example apps/api/.env

# 编辑环境变量
vim apps/api/.env
```

### 3. 构建应用

```bash
# 构建所有应用
pnpm build
```

### 4. 启动后端 API

```bash
cd apps/api
NODE_ENV=production node dist/main.js
```

或者使用 PM2 进程管理：

```bash
npm install -g pm2
pm2 start dist/main.js --name "labor-api"
```

### 5. 启动前端

前端是静态文件，可以使用任何 HTTP 服务器：

```bash
cd apps/web
# 使用 Node.js 简单服务器
npx serve -s dist -l 5173

# 或使用 Nginx 部署（推荐）
```

### 6. 配置 Nginx

创建 Nginx 配置文件：

```nginx
server {
    listen 80;
    server_name your-domain.com;

    # 前端静态文件
    location / {
        root /path/to/apps/web/dist;
        try_files $uri $uri/ /index.html;
    }

    # API 代理
    location /api {
        proxy_pass http://localhost:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
    }
}
```

## 生产环境配置

### 环境变量配置

在 `apps/api/.env` 中配置：

```env
# 数据库配置
DB_TYPE=mysql  # 可选: sqlite, mysql, postgres
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=your_secure_password
DB_NAME=labor_management

# 应用配置
NODE_ENV=production
PORT=3000

# JWT 密钥（如果使用认证）
JWT_SECRET=your_jwt_secret_key_here
```

### 安全建议

1. **修改默认密码**
   - 数据库密码
   - 应用密钥

2. **启用 HTTPS**
   - 使用 Let's Encrypt 免费证书
   - 配置 Nginx SSL

3. **防火墙配置**
   - 只开放必要端口（80, 443）
   - 限制数据库端口访问

4. **定期备份**
   - 数据库定期备份
   - 重要数据异地备份

### SSL 配置（Let's Encrypt）

```bash
# 安装 Certbot
sudo apt-get install certbot python3-certbot-nginx

# 获取证书
sudo certbot --nginx -d your-domain.com

# 自动续期
sudo certbot renew --dry-run
```

## 数据库选择

### SQLite（默认，适合小型部署）

**优点：**
- 无需额外数据库服务
- 配置简单
- 备份方便（复制文件即可）

**缺点：**
- 不适合高并发
- 性能有限

**配置：**
```env
DB_TYPE=sqlite
DB_PATH=data/labor_management.db
```

### MySQL（推荐，适合中型部署）

**优点：**
- 成熟稳定
- 性能优秀
- 社区支持好

**缺点：**
- 需要额外管理数据库服务

**配置：**
```env
DB_TYPE=mysql
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=your_password
DB_NAME=labor_management
```

### PostgreSQL（推荐，适合大型部署）

**优点：**
- 功能强大
- 支持复杂查询
- 可扩展性好

**缺点：**
- 资源消耗较大

**配置：**
```env
DB_TYPE=postgres
DB_HOST=localhost
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=your_password
DB_NAME=labor_management
```

## 数据备份与恢复

### SQLite 备份

```bash
# 备份
cp data/labor_management.db backups/labor_management_$(date +%Y%m%d).db

# 恢复
cp backups/labor_management_20240101.db data/labor_management.db
```

### MySQL 备份

```bash
# 备份
docker-compose exec mysql mysqldump -uroot -proot industrial_dev > backup.sql

# 恢复
docker-compose exec -T mysql mysql -uroot -proot industrial_dev < backup.sql
```

### PostgreSQL 备份

```bash
# 备份
docker-compose exec postgres pg_dump -U postgres industrial_dev > backup.sql

# 恢复
docker-compose exec -T postgres psql -U postgres industrial_dev < backup.sql
```

## 故障排查

### 常见问题

1. **容器启动失败**
   ```bash
   # 查看详细日志
   docker-compose logs api
   ```

2. **数据库连接失败**
   - 检查数据库服务是否启动
   - 确认环境变量配置正确
   - 检查网络连接

3. **前端无法访问 API**
   - 检查 API 服务是否正常
   - 确认 Nginx 配置正确
   - 检查防火墙规则

4. **性能问题**
   - 增加服务器资源
   - 优化数据库查询
   - 启用缓存
